# House Duck 블로그 우선 모션 홈 설계

## 목표

House Duck 홈을 짧은 브랜드 소개 뒤 최신 개발 글이 바로 보이는 구조로 바꾼다. 첫 화면은 아래 문구와 실제 게임 화면만 남기고, 프로젝트 소개와 연혁은 별도 `About` 페이지로 옮긴다.

> AI를 사용하지만,  
> 사람냄새 나는 게임과 소프트웨어,  
> 그리고 개발 일기를 보여주는 웹사이트

홈과 하위 페이지의 움직임은 같은 규칙을 쓰되, 콘텐츠를 가리거나 스크롤을 방해하지 않는다.

## 범위

- 한국어·영어·독일어·일본어 홈
- 새 `About` 페이지와 공개 가능한 세로 연혁·로드맵
- Quirky Ball·Project K 상세 페이지의 최신 미디어와 공통 전환
- 로컬 다국어 블로그 목록·글 페이지의 공통 움직임
- 기존 헤더의 House Duck 이미지 조합을 콘솔에서 쓰는 `HD` 마크 기반 표기로 교체

이번 범위에서 하지 않는 일:

- 콘솔 기능 또는 `console/analytics.js` 수정
- Tistory 광고·사이드바·편집기 구조 변경
- 비게임 앱과 공개 전 서비스 소개
- 새 애니메이션 라이브러리나 프론트엔드 프레임워크 추가
- Project K 게임 소스 수정

## 홈 정보 구조

### 1. 공통 헤더

- 콘솔 로그인 화면의 `HD` 마크 형태와 색을 공용 브랜드 요소로 재사용한다.
- `HD`는 CSS로 그리며 별도 장식 이미지를 추가하지 않는다.
- 헤더는 `Blog`, `Games`, `About`, `Support`, 테마, 언어만 남긴다.
- 화면 읽기 도구에는 `House Duck 홈`으로 안내한다.

### 2. 대표 말풍선

- 데스크톱은 왼쪽 말풍선과 오른쪽 아이폰 목업 묶음의 2열 구성이다.
- 말풍선에는 승인된 세 줄 문구만 넣는다. 부제, 설명문, 버튼은 넣지 않는다.
- 한국어는 승인 문구를 그대로 사용하고, 다른 언어는 뜻과 세 줄 리듬을 보존한 짧은 번역만 사용한다.
- 말풍선 꼬리는 오른쪽 아이폰 목업 묶음을 향한다. 첨부된 붉은 손그림 선은 구도 참고일 뿐 색·두께·형태를 복제하지 않는다.
- 모바일에서는 말풍선이 위, 목업이 아래로 이동하고 꼬리 방향도 아래쪽 목업을 향한다.
- 대표 영역은 화면 전체를 오래 점유하지 않는다. 최신 블로그 제목이 한 번의 짧은 스크롤 안에 나타나도록 높이를 제한한다.

### 3. 두 게임의 실제 화면

- Quirky Ball과 Project K를 각각 아이폰 목업 안에 배치한다.
- 목업에는 화면 테두리, 옆면, 측면 버튼, 카메라 영역, 홈 인디케이터를 포함한다.
- 데스크톱에서는 두 기기를 살짝 겹치되 게임 화면과 제목을 가리지 않는다.
- 각 기기에는 게임명과 상세 페이지 링크를 붙인다.
- 비게임 앱은 홈에서 노출하지 않는다.

### 4. 최신 블로그

- 대표 말풍선 바로 다음에 최신 글을 배치한다.
- 최신 글 한 개를 크게 보여주고 다음 글 다섯 개를 작은 카드로 보여준다.
- 한국어 글은 `blog.houseduck.in`의 원문으로 연결하고, 영어·독일어·일본어는 해당 로컬 번역 페이지로 연결한다.
- RSS 동기화가 실패하면 현재 작성된 기본 카드가 그대로 보여야 한다.
- 기존 큰 프로젝트 카드 목록은 홈에서 제거한다. 게임 소개는 아이폰 목업과 각 상세 페이지가 대신한다.

## About 페이지

- 첫 화면의 세 줄 문구를 짧게 다시 보여준 뒤 House Duck 소개와 제작 원칙을 이어서 설명한다.
- 완료된 일, 현재 작업, 다음 목표를 하나의 세로 연대기로 배치한다.
- 공개 항목은 `2026 · House Duck 1인 스튜디오 시작`, `첫 게임 · Quirky Ball 출시 준비`, `제작 중 · Project K`, `다음 목표 · Quirky Ball 출시 후 실제 지표로 개선` 네 개로 제한한다.
- 날짜와 상태는 Git·프로젝트 정본에서 확인된 내용만 사용한다.
- 게임 외 공개 전 서비스와 내부 운영 정보는 싣지 않는다.
- 스크롤할 때 연대기 선이 짧게 이어지고 항목이 순서대로 나타나지만, JavaScript가 없어도 전체 내용은 항상 보인다.

## Project K 미디어 교체

- 공개 사이트의 2026-08-03 이미지는 2026-08-10 이후 검증된 실제 클라이언트 화면으로 교체한다.
- 상세 페이지에는 대화 선택, 국가 지도, 농장 조작, 전쟁 진군을 대표 화면으로 사용한다.
- 홈페이지용 약 10초 영상은 안정된 커밋의 실제 런타임을 녹화해 다음 순서로 편집한다.
  1. 대화 선택
  2. 지도와 차량 이동
  3. 농장 수확
  4. 전쟁 진군
- 장면 전환은 짧은 디졸브만 사용하고 홍보용 가짜 UI나 연출용 목업을 섞지 않는다.
- 배포 영상은 세로 MP4 한 개와 정적 포스터 한 장만 둔다. 홈페이지 표시 크기에 맞춰 압축하고 자동 재생 중 소리는 내지 않는다.
- 작업 중인 Project K 공유 작업트리는 수정하지 않는다. 녹화는 안정된 커밋을 별도 실행해 만든다.

## 모션 규칙

### 대표 문구

- 전체 문장은 처음부터 HTML에 존재해 검색과 접근성을 유지한다.
- 시각 연출만 한글자씩 나타나게 한다. 글자당 약 35~45ms, 쉼표와 줄바꿈에는 짧은 멈춤을 둔다.
- 입력 완료 뒤 커서는 두 번만 깜빡이고 사라진다.
- `prefers-reduced-motion`에서는 즉시 전체 문구를 보여준다.

### 진입과 스크롤

- `HD` 마크가 한 번 짧게 자리 잡고, 말풍선과 두 아이폰이 같은 방향 흐름으로 나타난다.
- 스크롤 콘텐츠는 8~12px 이동, 약한 흐림 해제, 불투명도 전환만 사용한다.
- 콘텐츠는 기본 상태에서 보인다. JavaScript는 보이는 요소를 숨기는 대신 교차 시점에 Web Animations API로 짧게 재생한다.
- 브라우저가 지원하면 View Transitions API로 홈·About·게임 상세 전환을 부드럽게 연결하고, 미지원 브라우저는 즉시 이동한다.

### 상호작용

- 링크·카드·목업은 같은 강조색과 2px 안쪽 이동 규칙을 공유한다.
- 끝없는 부유, 파티클, 큰 패럴랙스, 가로 스크롤 강제, 스크롤 위치 탈취는 사용하지 않는다.
- 화면 밖 영상은 일시 정지한다. 데이터 절약 또는 모션 축소 환경에서는 포스터를 우선한다.

## 구현 경계

- 기존 `assets/brand-site.js`의 메뉴·테마·언어·블로그 피드 로직을 유지하고 필요한 모션만 최소 추가한다.
- 홈 전용 배치는 `assets/studio-home.css`, 공통 전환과 `HD` 마크는 `assets/brand-site.css`에 둔다.
- Project K 고유 배치는 `assets/project-k-site.css`에 유지한다.
- 공통 동작을 위해 새 라이브러리나 빌드 단계를 추가하지 않는다.
- 네 언어 홈과 상세 페이지는 현재 정적 HTML 구조를 유지한다.

## 오류와 대체 동작

- 블로그 피드 실패: 작성된 기본 카드 유지
- 영상 로드 실패: 포스터와 게임 상세 링크 유지
- IntersectionObserver·Web Animations·View Transitions 미지원: 애니메이션 없이 전체 콘텐츠 표시
- JavaScript 차단: 문구, 링크, 글 목록, 이미지가 모두 사용 가능
- 자동 재생 차단: 포스터를 보여주고 사용자가 영상을 재생할 수 있게 한다.

## 검증

- 구조 회귀: `bash scripts/check_public_repo.sh`, `bash scripts/check_brand_site.sh`
- 정적 UI 회귀: `node scripts/test_public_ui_regressions.js`, `node scripts/test_brand_catalog.js`, `node scripts/test_brand_feed.js`
- 브라우저 회귀: `npm run test:e2e`
- 네 언어에서 홈·About·Quirky Ball·Project K·블로그 목록을 확인한다.
- 데스크톱 1440×900, 모바일 390×844에서 잘림, 가로 넘침, 말풍선 꼬리 방향, 목업 옆면·홈 인디케이터, 터치 영역을 확인한다.
- 모션 축소, JavaScript 차단, 영상 로드 실패, 블로그 피드 실패 상태를 각각 확인한다.
- 완료 전 시작·종료 `git status --short`를 비교해 `console/analytics.js`와 Project K 공유 작업트리가 그대로인지 확인한다.

## 완료 기준

- 홈 진입 시 승인 문구가 말풍선 안에서 한 글자씩 나타나고 꼬리가 아이폰 목업을 향한다.
- Quirky Ball과 최신 Project K 실제 영상이 모두 보인다.
- 최신 블로그가 대표 영역 바로 뒤에서 한눈에 읽힌다.
- 소개·연혁은 별도 About 페이지에서 세로로 탐색할 수 있다.
- 홈과 하위 페이지가 같은 짧은 디졸브·상호작용 규칙을 쓴다.
- 모션이나 영상이 실패해도 내용과 링크가 사라지지 않는다.
- 기존 콘솔 변경과 Project K 작업 파일이 수정되지 않는다.
